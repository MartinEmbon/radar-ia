# Radar IA · 2026-11-24

> [!summary] En 30 segundos

Anthropic le suma al estándar MCP skills, tareas en segundo plano y confirmaciones del usuario (elicitation), tres piezas que importan para integrar agentes con sistemas reales. iFood muestra cómo corre agentes de código en más de 15.000 repositorios a unos 4 centavos de dólar por ejecución. ## Para tu trabajo

### 1. MCP gana skills, tareas largas y confirmaciones del usuario
**Qué pasó:** Anthropic anunció tres novedades de MCP en Claude. *Skills over MCP* (beta pública): el servidor publica skills junto con sus herramientas y Claude las carga solo cuando hacen falta. *Tasks* (disponibilidad general): el servidor ejecuta operaciones largas, o bucles enteros de agente, en segundo plano. *Elicitation* (disponibilidad general): el servidor pausa una acción y le pide datos o confirmación al usuario con un formulario o un link. Los ejemplos que da son Supabase (confirma costos y SQL destructivo), Railway y GitHub (pide escribir el nombre del repo antes de borrarlo). File Uploads, para mandar archivos a un servidor MCP sin pasar por el contexto, llega "próximamente". Según el post, son parte del estándar abierto y deberían funcionar en otros clientes compatibles.
**Qué podés hacer con esto:** Al diseñar o evaluar un servidor MCP para un cliente, pensá qué operaciones largas conviene exponer como tasks y qué acciones sensibles deberían frenarse con una confirmación humana, en vez de resolverlo con prompts. Y fijate si las instrucciones de uso de tus conectores se pueden empaquetar como skill dentro del propio servidor, así se actualizan con él.
**Fuente:** [Claude: MCP servers can now ship skills, run tasks, and more](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)

### 2. iFood: agentes de código en más de 15.000 repositorios con una API central
**Qué pasó:** iFood armó una plataforma interna (Remote Agents Platform), una API REST que lanza tareas de programación con agentes en sandboxes aislados por ejecución. Cada corrida mezcla pasos deterministas (clonar, preparar la rama, publicar el merge request) con una etapa agéntica. Reportan más de 25.000 ejecuciones, más de 27.000 millones de tokens y un costo promedio de 0,04 dólares por ejecución. En su producto interno de seguridad, la precisión de las correcciones y las vulnerabilidades resueltas se más que duplicaron. Aprendizajes: el cuello de botella fue la infraestructura de ejecución y no el caso de uso, y exigir salidas con esquema fijo permite clasificar éxitos y fallas sin revisar a mano. El artículo no detalla políticas de aprobación ni controles de acceso.
**Qué podés hacer con esto:** Usalo como caso para clientes que quieren "agentes en todo el parque de código": el patrón es una entrada central, sandbox por tarea, pasos deterministas alrededor del agente y contratos de salida verificables. Es muy parecido a cómo se piensa un flujo de integración, y ahí hay un ángulo para Digibee.
**Fuente:** [OpenAI: How iFood scales coding agents across 15,000 repositories](https://openai.com/business/customer-stories/ifood)

## Para Digibee
- **Agentes y MCP:** con tasks y elicitation, MCP cubre dos huecos que los clientes preguntan: procesos largos y aprobación humana en acciones destructivas. Buen momento para mostrar cómo se expone un flujo de integración como servidor MCP con esos controles.
- **Digital workers:** iFood es un ejemplo de lo que se repite: lo difícil es la infraestructura de ejecución, el aislamiento y la verificación de resultados, no el modelo. Eso es terreno de una plataforma de integración.
- **Competencia:** nada nuevo hoy sobre Copilot Studio, n8n, Workato y similares.
